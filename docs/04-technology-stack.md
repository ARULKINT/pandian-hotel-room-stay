# 4. Technology Stack

## 4.1 Stack Summary

| Technology | Version | Category | Purpose | Used In |
|---|---|---|---|---|
| JavaScript (ES modules) | ES2020+ (native, no transpiler) | Language | Both frontend and backend logic | Entire codebase |
| Node.js | 20.6+ (relies on `process.loadEnvFile`) | Runtime | Backend server runtime | `backend/` |
| Express | ^5.2.1 | Web framework | HTTP routing, JSON body parsing, CORS, error middleware | `backend/server.js` |
| cors | ^2.8.6 | Middleware | Cross-origin access control between the Netlify frontend and Render backend | `backend/server.js` |
| pg (node-postgres) | ^8.13.1 | Database driver | Postgres connection pool + queries when `DATABASE_URL` is set | `backend/store.js` |
| Vite | ^5.0.0 | Build tool / dev server | Frontend dev server, production bundling, static asset pipeline | `frontend/` |
| Tailwind CSS | latest (CDN, `cdn.tailwindcss.com`) | CSS framework | Utility-class styling with a custom Material-Design-3-inspired token theme (colors, spacing, type scale) configured inline in `index.html` | `frontend/index.html`, all page markup |
| Google Fonts | — | Typography | Playfair Display (headlines), Plus Jakarta Sans (body/labels), Material Symbols Outlined (icons) | `frontend/index.html` |
| Node.js `crypto` (built-in) | — | Security | scrypt password hashing, `timingSafeEqual`, `randomBytes`/`randomUUID` for tokens and booking IDs | `backend/server.js` |
| Node.js `fs` (built-in) | — | Persistence | Reads static reference JSON; writes `bookings.json` in local/no-database mode | `backend/server.js`, `backend/store.js` |
| concurrently | ^8.2.2 | Dev tooling | Runs frontend + backend dev servers with one command at the repo root | root `package.json` |
| Render | — (free web service plan) | Hosting | Runs the backend Node process | Deployment |
| Netlify | — (free tier) | Hosting | Serves the built frontend as static files | Deployment |
| Neon | — (free Postgres) | Database hosting | Optional durable storage for `bookings` | Deployment (recommended for production) |
| GitHub | — | Source control / CI trigger | Both Render and Netlify auto-deploy on push | Deployment |

## 4.2 What Is Deliberately *Not* Used

| Not used | Note |
|---|---|
| React / Vue / Svelte / any SPA framework | Hand-rolled `render()`/`mount()` pattern instead — see [05](05-project-structure.md) and [09](09-api-documentation.md)-adjacent rationale in [03-system-architecture.md](03-system-architecture.md) §3.9 |
| TypeScript | Plain JavaScript throughout; no type-checking layer |
| An ORM (Prisma, Sequelize, TypeORM, …) | `store.js` talks to Postgres with hand-written parameterised SQL via the raw `pg` driver, storing each booking as a single `JSONB` document rather than a normalised relational schema |
| A CSS build step / PostCSS / a compiled Tailwind config file | Tailwind is loaded from the CDN's JIT script at runtime with an inline `tailwind.config` `<script>` block — there is no `tailwind.config.js` file in the repo |
| Any test framework (Jest, Vitest, Playwright, …) | No automated test suite exists — see [17-testing.md](17-testing.md) |
| A payment SDK (Stripe, Razorpay, …) | Payment method selection is UI-only; no transaction is ever processed — see [24-known-issues.md](24-known-issues.md) |
| Any AI/ML library or LLM API | Not part of this project — see [13-ai-ml.md](13-ai-ml.md) |

## 4.3 Dependency Files

| File | Role |
|---|---|
| `package.json` (repo root) | Orchestrates `npm run dev` for both tiers via `concurrently` |
| `frontend/package.json` | Vite only (`dev`, `build`, `preview` scripts); no runtime dependencies — the frontend ships zero npm packages to the browser |
| `backend/package.json` | `express`, `cors`, `pg` |

## 4.4 Version Policy

Dependencies are pinned with caret ranges (`^`) as generated by `npm install`, not exact-pinned. No `package-lock.json` divergence was found between what's declared and what's installed at the time of writing. There is no automated dependency-update tooling (Dependabot/Renovate) configured in this repository.
